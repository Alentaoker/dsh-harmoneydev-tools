# 维护升级

以 [AI 安装指南](AI_INSTALLATION.md) 为完整操作顺序。这里补充本次数据格式与版本边界。

## 0.1.2 → 0.2.0

- 不删除或重写旧运行器报告和日志。首次读取历史时建立小型 `record.json`，保留原会话归属。
- 无归属旧记录只出现在主动选择的全部历史中；不自动认领或给 ID 加前缀。
- 新动作缓存按会话区分。旧流程记录仍能查看，不能保证旧缓存跨会话复用。
- 调整复测是新运行，记录 `parentRunId`／`relation`，保留原参数、结果、日志和截图。
- `list_runs/get_report/get_logs/cancel/replay/retry` 从工具调用者的实际会话取范围。旧脚本直接访问 HTTP 报告接口时必须补充 `sessionId`；全部历史读取需显式 `scope=all`，写入仍只允许当前会话。
- 磁盘中遗留的准备／运行状态在冷启动显示“已中断”，控制释放状态不凭空确认。

## 宿主升级

本次没有升级 DSH 宿主。当前兼容补丁基于 0.2.0-rc.2；新的宿主版本需要重新核对工具协议、客户端 slot、composition、依赖和关闭机制。插件版本、宿主版本、源码提交、安装来源分别记录。

使用 `dsh-plugin-upgrade-skill` 时，读取其完整 `SKILL.md` 和匹配的版本迁移参考，先确认目标版本和失败现象。不要直接将当前宿主的预设替换成旧版补丁，也不要用 README 的安装成功代替冷启动与实机证据。
