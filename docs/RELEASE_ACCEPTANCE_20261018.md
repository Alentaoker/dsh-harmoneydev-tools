# Harmony rc.8 / dshVerify rc.1 本机运行验收

版本：dshHarmony **0.5.0-rc.8** / dshVerify **0.5.0-rc.1**（安装标识 dsh-e2e）。目标发行标识 `v0.5.0-rc.8-e2e-0.5.0-rc.1`，属于 RC 预发布。

## 环境与证据范围

Windows x64、DSH 0.2.0-rc.2、Node 24.21.0；实际宿主内置 Node 24.18.1 / Cordis 4.0.4。设备为 USB 连接的 nova 14 Ultra / MRT-AL10，设备标识在公开报告中省略。

运行验收使用真实构建产物、真实宿主 Cordis 与附件提供器、真实 Harmony 设备后端和当前手机。确定性的工具调用由 Codex 编排；没有启动独立内层 AI 验收器，也没有把夹具回执当成手机效果。网页检查使用运行中的 DSH 与正式 HTTP 路由。测试数据放在独立验收目录；原有媒体、日志与会话草稿保留。

## 验收发现与修复

1. **宿主依赖兼容**：`{required,optional}` 不是 Cordis 4.0.4 支持的声明，插件曾等待不存在的 required/optional 服务。改为必需服务数组与条件子上下文；可选服务读取使用 `ctx.reflect.get`，后加载、移除、重新加载 Harmony 均能正确建立/清理关联。
2. **采集状态停留在 starting/0**：采集在进行，但读取报告只看启动时的磁盘快照。当前作用域的报告现在合并真实运行状态和计数，采集中标为 collecting；停止后仍读取持久记录。新增回归用例。
3. **静态录屏尾部被截短**：约 28 秒的静态录制曾只生成约 2 秒视频。编码器只在画面变化时出帧，原实现固定每帧时长，丢掉了最后一次变化到停止之间的时间。现在缓存一个编码样本，以下一帧/实际停止时刻确定时长。真机复验：实际静止等待 **8.013 秒**，MP4 **8.025 秒**；没有向手机制造触摸或伪造画面。新增直接读取 MP4 时长的回归用例。
4. **旧测试契约**：旧 harness-adapter 仍要求已删除的 E2E_REQUIRED / busy 路由，已更新为真实 wrapper 的人工模式控制拦截、无轮次 help 与非法参数检查。

## 大日志与性能

90 秒实际设备 HiLog 采集获得 21183 行。10 万行以上压力使用本机已留存的 **147576 行真实设备解码日志**，没有扩写或重复生成测试日志。

- 输入 18,208,902 字节，独立日志库导入约 **1.60 秒**。
- 首/尾 1000 行各约 **54 / 51 毫秒**，实际响应约 317 / 311 KB。
- 会话跨文件正文搜索命中 8 份文件、43919 行，约 **2.57 秒**；另一会话命中 0。

这是本机后端实测，不是浏览器完整绘制耗时或实时流入十万行时的 CPU/内存峰值承诺。实时工作台的 100000 行 / 128 MiB 上限与虚拟渲染保留。

## 保留边界

- 原厂 H.264 通道在完全静止页面冷启动时，本机曾先只提供兼容截图；没有关键帧时录屏启动显式超时，不生成空视频。页面发生实际变化后原生视频与录屏恢复。自动连接没有要求用户点“接入实时视频”，也未通过模拟触摸制造首帧。
- 物理转屏、拔插 USB、第二台真机、真实软链攻防及其它宿主/系统未完成现场验收；几何、断连与安全边界只覆盖现有自动回归。
- 观察和取消使用真实工具 handler/设备，由确定性调用编排；没有额外消耗供应商模型额度来运行一段独立的 DSH 模型完整对话。公开结果不把它称为独立 AI 验收通过。
- 不升级 DSH 宿主、不改变凭据/权限，不发布手机截图、真实日志、用户数据或验收目录。
