# 可移植性与安装验证

记录日期：2026-10-16。配套插件为 dshHarmony 0.5.0-rc.4 / dshE2E 0.4.0-rc.3，发行修订 r2。插件运行源码和日志格式与原版一致；r2 修复源码打包遗漏，并更新安装说明。

## 验证方式

在当前 Windows x64 电脑上，使用已发布 ZIP，核对 SHA256 后解压到含空格和中文的新来源目录，并使用全新 DataHome。由官方 CLI 初始化独立 web profile，未复制原 profile、模型、登录或会话配置。使用随宿主提供的真正 Node 24.21.0，以及 npm 10.5.0，在 Windows PowerShell 5.1 执行安装脚本。

测试先安装到来源 A；修复打包规则后，从新生成的完整源码来源 B 再构建并正式登记到同一测试 profile，检查来源迁移和已导入日志保留。两个来源均单独执行 npm ci，未复用开发目录的 node_modules。

原桌面环境保持运行，不更改其登记。开始前后核对原 desktop profile 的 package.json、composition patch 和 pnpm 锁哈希；测试结束只停止自己创建的临时 CLI 服务，测试数据与证据留在本机。

## 发现并修复的源码包缺陷

rc.4 原包能够依赖安装、构建、登记和冷启动，但从包内执行 Harmony 完整回归时，一项测试模块因缺少 session-reader.ts 无法构建。原因是打包器曾把所有 `session` 开头的非测试文件排除，误删了会话实现模块。

r2 改为保留 session 开头的源码文件，继续排除会话 JSON/JSONL、日志、密钥和本机凭据。新增真实打包用例，校验源码保留、敏感数据排除、manifest 哈希及禁止覆盖已有发行目录。此修复只影响发行源码完整性；手机控制和视频实现未改变。

修复后的独立来源 B 完整回归为 Harmony 84/84、E2E 52/52，打包/登记脚本 3/3。离线导入/worker、会话隔离、GZ、分析路径、来源迁移保留原日志、冷启动与原桌面配置未变等 16 项检查通过。最终 ZIP 另核对实现文件与这份已验来源逐份一致，并重新执行 manifest/PowerShell 5.1 预检。

安装指南的 10 段 PowerShell 代码块通过 Windows PowerShell 5.1 解析检查，11 份主要说明文档中的 61 个相对链接均可解析。语法检查不等同执行所有占位符示例；实际安装执行的是前述独立环境中的真实路径命令。

## 支持边界

| 项目 | 当前边界 |
|---|---|
| Windows x64 / DSH 0.2.0-rc.2 / Node24 | 当前验证目标；本轮使用 Node 24.21.0，此前开发回归使用 24.19.0 |
| 同机新路径、全新数据和 profile | 已实际验证；不等同另一台实体电脑 |
| 另一台实体 Windows 电脑 | 尚未实测；不能承诺其网络、驱动、权限和安全软件环境全部相同 |
| Windows ARM64、macOS、Linux、其它 DSH 版本 | 未完成适配验收；安装预检应拒绝不支持的目标 |
| 手机/HDC/驱动 | 按目标电脑配置；不从原电脑复制路径或设备授权 |
| 原厂二进制 HiLog | 另需本机 hilogtool 和对应日志字典；不随包分发 SDK/字典 |
| 已认证网页 UI/API、真实模型、终端原生模块 | 本轮独立环境未验收，不以 401/403 或冷启动替代 |
| 解锁后 H.264、真实桌面 PUT 保存及原生拖放 | 沿用 VALIDATION.md 的待验状态；本轮未操作手机 |

## 在另一台电脑复验

按 [AI 安装指南](AI_INSTALLATION.md) 使用该电脑的实际路径，先做哈希校验和 PlanOnly，再完整安装并冷启动。优先验证离线明文/GZ 导入、查询、会话隔离和分析路径；再分别配置 HDC、驱动、SDK 工具与模型，验证需要它们的能力。不要通过复制原 DataHome、用户密钥或改宿主兼容豁免来使测试通过。

升级与回退按 [AI_UPGRADE](AI_UPGRADE.md)；发行修订和插件版本在 [README 版本表](../README.md#版本进度) 分别记录。
