# 实时视频占用与恢复改进

日期：2026-10-15。优先级 P0；保留之前的日志验收遗留。

## 本次症状和依据

截图中的英文错误来自原生视频启动前的进程检查。实际检查手机发现 DevEco 的 `libscreen_casting.z.so` 进程；本机 DSH broker/native-video 目录没有活动归属文件。设备进程 PID 是手机 PID，不能混同于 Windows 的 DSH 宿主 PID。

不能仅凭这次截图推断 DSH 多窗口共享失效，也不能仅凭外部进程还在就推断 DevEco 窗口仍在正常看视频。未取得归属证据的外部进程不自动清理。

## 处理行为

- DSH 窗口、网页及录像复用每台设备一个带认证的本机视频 broker；控制权仍独立。
- DevEco/其他软件的独立编码进程存在时，返回来源、设备 PID、等待释放指引，并显示“重试实时视频”。当前适配器不接管外部投屏 RPC，关闭该软件的设备投屏后再使用 DSH 视频。
- 等待期间约 1.5 秒刷新一次截图，约 10 秒重新尝试视频。截图失败保留占用原因和重试入口；后台隐藏/页面关闭取消自己的订阅和定时器。
- DSH 已登记且宿主确认死亡的残留仍按原逻辑回收其准确扩展、PID、文件和转发；无有效归属记录不按扩展名前缀批量杀进程。
- 共享服务正在正常释放时，订阅端最多短暂重试 2.5 秒，不删除活服务记录、不创建并行编码器。仍不可达则说明本机服务 PID，保留再次重连能力。
- 启动失败先送达结构化错误，再清理订阅；跨服务只转发错误原因、来源和 PID 等必要字段，令牌和路径不外传。
