# 实时视频连接阶段与恢复

适用 dshHarmony 0.5.0-rc.6。本页说明设备画面为什么显示“连接中 / 等待解锁 / 兼容投屏 / 恢复中”，以及每个阶段真实的采集开销。视频通道仍是被测的原生 H.264，截图预览仍是兜底，两者不混为一谈。

## 七个阶段

| 阶段 | 触发 | 视频尝试 | 截图兜底 |
|---|---|---|---|
| `offline` | 设备不在线、面板未激活或页面隐藏 | 不尝试 | 2 s |
| `waiting-unlock` | 被动读到锁屏或熄屏 | 暂停 | 2 s |
| `busy` | 外部投屏进程占用编码通道 | 每 10 s 探测释放 | 1.5 s |
| `connecting` | 已解锁但首帧未到 | 是 | 750 ms |
| `live` | H.264 正在出帧 | 是（已连接） | 1 s（仅锁屏心跳） |
| `compatible` | 本机解码/组件不可用，改用截图 | 周期性重试 | 750 ms（约 1～2 张/秒） |
| `recovering` | 兼容通道自身失败 | 周期性重试 | 750 ms |
| `paused` | 面板暂停或页面不可见 | 不尝试 | 4 s |

锁屏不再是“视频错误”。以前它与普通失败共用 30～120 秒退避，现在单独判断：确认锁屏后只做低频检查与低频预览，解锁后立刻重连。

## 自动连接与恢复

- 打开设备页且设备在线、已解锁：不需要点击任何按钮，直接尝试实时视频。
- 手机锁屏或熄屏：显示等待状态，不再每 120 ms 抓一张截图。
- 手机唤醒并解锁：被动探针发现 `awake && !locked` 后立即结束等待窗口，跳过剩余退避。
- 点击“唤醒设备”成功：立即重新检查视频通道。
- USB 重连、页面重新可见：设备刷新与可见性变化都会重建订阅并立即检查。
- 外部投屏释放：`busy` 阶段每 10 s 探测一次，占用消失后自动恢复。
- 普通连接失败：先有界重试（3 次），再按原因进入兼容模式或占用等待。兼容预览窗口同样响应解锁：确认“不可用→可用”后立即结束窗口重试实时通道，不再等该窗口 30～120 秒的预算。
- 不循环发送电源键，不自动清理外部投屏进程；“释放占用并重连”仍需用户确认和手动控制租约。

目标：设备确认已解锁后 5 秒内出现真实画面。该目标需要真机测量，当前候选版未验证。

## 锁屏探测

`GET /api/harmony/screen-state?serial=…` 只读执行 `hidumper -s ScreenlockService -a -all`，解析 `screenState`、`interactiveState`、`screenLocked`，**不发送任何输入**。读不到锁屏状态时返回错误，不假设为已解锁。

探测时机：

- 首帧前不探测（没有理由先花一条设备命令）。
- 出现失败、或已知锁屏/熄屏时开始探测。
- 等待状态约 2 s 一次；实时出帧后降为 15 s 心跳，只用于发现中途熄屏。
- 同一设备的并发探测共享一次命令，2 s 轮询不会堆积 `hidumper`。

## 预览积压预算

H.264 帧之间存在依赖，不能任意丢帧。预览积压的处理方式是**等到下一个关键帧**，不是逐帧丢弃：

| 预算 | 值 | 说明 |
|---|---|---|
| 积压字节 | 1.5 MB | 压缩数据仍在队列中的字节数 |
| 积压时间 | 200 ms | 最早一条未消费数据的滞留时间 |
| 解码队列 | ≤ 8 帧软上限 | 超过先做有界背压（1 s）；仍超载则重连取新 IDR |
| 关键帧等待 | 2 s | 超时仍未等到关键帧则强制重连 |

超预算时停止提交依赖帧，直到关键帧重新建立参考链。这台设备的视频源**只在画面变化时出帧**，所以只等关键帧可能永远等不到（画面静止时既不补帧也不补 IDR），预览就会停在旧画面。因此等待是有界的：2 秒内没有关键帧就主动重连取新 IDR，诊断里的“重同步”计数记录这类恢复。设备端编码与主机端录像不受影响：预览追帧不截断录像。

## 诊断指标

“更多工具 → 连接诊断”显示实测值，不显示推测值：

| 指标 | 含义 |
|---|---|
| 通道 / 阶段 | `video`/`frames` 与上面的阶段名 |
| 绘制帧 / 绘制帧率 | 真正画到画布上的帧数与本次连接的平均帧率 |
| 跳过依赖帧 | 因积压预算被跳过、等待关键帧的帧数 |
| 首帧 / 恢复 | 本次连接到首帧、从失败恢复到出帧的耗时 |
| 解码队列 / 预览积压 | 当前队列深度与未消费字节 |
| 重同步 | 积压后等不到关键帧、强制重连取新 IDR 的次数 |
| 锁屏探测 / 手机状态 | 探测次数与最近一次读数 |
| 建议画质 | 结合面板宽度和解码压力给出的建议档位 |

“建议画质”只给建议，不自动切档：切换档位会重启编码器，因此仍由用户在设置里决定。低变化画面的低帧数不是故障；“优先硬解”是请求而不是证据，硬件解码是否生效仍以实测为准。
