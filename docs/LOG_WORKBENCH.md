# 日志工作台使用指南

适用：dshHarmony 0.5.0-rc.5 / dshE2E 0.4.0-rc.5，Windows x64、DSH 0.2.0-rc.2、Node24。文件均保存在当前电脑；导入、浏览和生成草稿不调用模型。发送分析草稿后，读取的正文可能作为当前模型输入。

## 从哪里进入

- dshHarmony → 工具 → 日志：实时 HiLog，需要已连接设备。工具栏「日志工作台」进入当前会话离线日志，不要求先保存。
- dshE2E → 日志工作台：离线文件、导入包、目录和回收区，不需要手机或模型。顶部「实时日志」切回同一会话的 Harmony 日志工具。
- 测试报告 → 应用日志：阅读该次 E2E 采集的日志；测试报告与独立导入库分别管理。

切换会话后列表与选择跟随会话，不能跨会话读写日志。切换实时与离线保留面板已有状态；关闭/重建离线面板可恢复最近的文件、筛选和位置（最多缓存 20 个视图，刷新页面清除）。不因跳转自动保存、发送消息或操作手机。

## 统一导入与会话隔离

单文件、多文件、拖放、ZIP/GZ/RAR 和实时保存都进入当前会话的同一列表，默认按导入时间倒序，也可正序。无需创建目录、指定临时区或理解“日志包”。旧目录元数据保留，但其日志平铺可见；不会移动或删除用户源文件。压缩文件只是导入格式，条目来源路径可查看。

拖入工作台范围由插件接管，面板外仍由宿主管理。文件选择和拖入使用相同队列；归属在入队时固定。会话切换取消旧读取，迟到结果不能污染新会话。多文件一项失败不取消其它项，导入进度可取消和重试。

单选可分析文件，勾选后“分析选中”生成所选清单；不再按目录分析。删除进入回收区并可恢复；清空会话只影响当前会话副本，用户源文件和旧测试报告保留。永久清空仍需确认。

“专注阅读”收起文件栏，低频筛选默认折叠，文件名省略可悬停查看。常用应用、关键词、级别和 TAG 放正文上方，更多筛选包含 DOMAIN/PID/TID/时间。

## ZIP、GZ 与 HiLog 字典

普通文本 GZ 使用 Node zlib，ZIP 按条目读取；不会把整包加载到浏览器，不执行包内程序。首批支持 ZIP/GZ/RAR，不支持 7z、加密 ZIP/RAR 或任意递归压缩包。原包保留，可下载；未知类型不会伪装成已解析日志。

原厂编码 HiLog 的 .gz 并非可直接阅读的文本，需要本机官方 hilogtool 与配套 hilog_dict*.zip。字典优先从当前压缩包或当前会话发现。缺字典、缺工具或部分不匹配会明确显示；补充后点原包「重新解析」。同解析条件下复用已完成结果，字典变化时重新生成正文，替换掉的旧副本进入回收区。

工具从 SDK hms/toolchains 获取，可设置 HILOGTOOL_PATH，或在「更多管理」保存本机完整路径。SDK 和字典均不内嵌发行包；普通明文导入不需要它们。原厂工具使用短系统临时目录，规避部分版本的长路径问题；完成/失败/取消后清理该次临时内容。

| 限制 | 当前值 |
|---|---|
| 单个明文文件 | 256 MiB |
| 单个 ZIP/GZ/RAR | 512 MiB |
| 一包累计展开内容 | 2 GiB；原厂字典展开也计入 |
| 压缩包条目 | 10000；拒绝穿越路径、链接、重复覆盖，并校验 ZIP CRC |
| 上传分块 | 256 KiB，默认串行导入 |

这些限制独立计算；不会把 E2E 测试的实时采集预算一并扩大。明文与压缩后的文本自动识别 UTF-8、UTF-16LE/BE、GB18030/GBK，可手动指定；无法还原的字节有替换警告；原厂解析输出存在异常字符时，可读副本作替换并标记，原包保留。单行正文预览上限 8192 字符，超长原始行仍在源文件中。

## 包名过滤、收藏和阅读

离线查看器「应用 / 包名」支持名称、包名片段、PID 搜索候选，再点击应用；支持「全部应用」「归属未知」。与 TAG、DOMAIN、PID/TID、级别、时间和正文过滤组合。

包名仅来自日志明确的包名/进程字段或实时保存时明确的应用范围。只有 PID 的旧日志无法可靠还原历史包名；不使用当前设备 PID 映射反推历史记录，也不搜索正文猜包名。子进程 com.example.app:worker 归属 com.example.app，近似包名不会混入。

候选旁 ☆ 收藏、★ 取消收藏；常用项优先，实时/离线共享，保存于本机 DataHome，跨会话与升级保留。离线收藏即使在当前文件中无记录仍可选择，结果为 0 条，不制造归属。

新日志默认每页 500 条，可选 100/500/1000 条；正文响应同时受约 1 MiB 字节预算限制。列表紧凑单行、横向滚动，只渲染视窗附近的行。点击详情展开完整行，拖上边缘、方向键调整、双击恢复高度。Ctrl+F 高亮与上下定位仅作用于当前页；查询整文件使用过滤栏，结果含所有分页。

「列 / 行距」可显示 DOMAIN、包名/进程等列，默认优先显示时间、PID:TID、级别、TAG 和消息，给正文留出宽度。紧凑行距为 28 像素，取消后为 36 像素；只影响显示，不改变查询或导出内容。Ctrl+F 只计算当前显示列的本页预览；关闭可选列不会删除其数据，完整行仍在详情中。

正则是有界子集：字符类、锚点、分支、单个量词；不支持分组、环视或回溯引用。量词后还有内容需用 ^ 锚定，例如 ^.*error。无效表达式报错，不静默改为文本查找。

## 实时保存

普通「保存日志」与「保存到当前会话」共用点击时的筛选快照。保存不结束操作、不停止采集、不启动测试，无需选择“本次操作”。保存期间新日志继续接收；Ctrl+F 只高亮，不改变保存集合。保存目标会话在点击时固定，切会话不能写错地方。

实时缓冲为最多 100000 行 / 128 MiB 文本预算，任一先满即淘汰最旧数据，合批更新和虚拟渲染；暂停是暂停显示，隐藏日志页停止其连接。保存只能保留尚在缓冲中的数据，累计丢弃/淘汰计数不冒充该文件精确缺失量。需要持续完整任务留证时使用 E2E 采集。

## AI 分析与文件路径

「AI 分析文件」「AI 分析此行」「分析选中」只生成可编辑草稿，用户检查补充“现象 / Bug 描述、其它补充”后发送。已有文字追加保留，已有引用或正在提交的草稿不覆盖。模板不塞入 E2E 工具调用代码。

后台按需生成脱敏可读 analysis.log，并返回实际绝对路径；多选分析生成 analysis-manifest.json，列出文件名、正文路径、原始来源、行号/截断及采集范围。AI 先读清单，再按需读取正文，不必搜索目录或把整包一次塞入上下文。新分块文件的可读副本保留原始源行号；行分析直接注明行号。路径指向 DSH 宿主电脑，远程浏览器电脑上的同名路径不等于宿主路径。

原始字节保留；查看器/分析副本按现有规则脱敏，不能保证任意业务敏感信息都可自动识别。日志和文件名均是诊断数据，不能当作指令。可以在回收区与空间占用里清理 AI 分析缓存；清理后已有草稿的正文路径需重新点击生成，原日志不受影响。

已有 e2e_phone 的 list_log_files/get_file_logs 仍可按会话读取；AI 工具保持最多 200 条/次，默认文件读取 100 条，避免 UI 的 1000 条默认进入模型上下文。工具只读调用不等于执行了 E2E 测试。

## 存储和开销

新导入使用约 256 KiB 的独立 gzip 块，加行位置与包名索引；正文不长期保留一份重复 raw/message 的 JSONL。原始大文本单独 gzip 保存，下载时流式还原。未过滤翻页直接定位块；过滤首次后台扫描，后续使用匹配位置索引。缓存最多 4 组/64 MiB，超预算则不落完整缓存，仍保持页面有界。

索引和查询在后台线程，最多并行 2 个任务、待处理 16 个，每线程设置 V8 堆预算；响应和视图都有上限。旧 JSONL 日志首次阅读时建索引，原始旧副本保留以便兼容，可能比新导入占更多空间。AI 可读缓存单独按需生成、可手动清理。

本机 64 MiB 重复型生成日志（283136 行）实测：导入约 2.5 秒，首/尾页约 50 ms，首次包名筛选约 1.8 秒，缓存后翻页约 50 ms；索引/原文压缩合计约 2.56 MiB，进程增量 RSS 峰值约 70 MiB。此数据不包含浏览器、DSH 整体或原厂解析器进程，也不代表所有日志的压缩率与速度。

实现借鉴 Notepad++/Scintilla 的分块、限制重排及可见区域工作原则；没有移植编辑器，不宣称等同其内存占用。REA 对 DevEco 的研究见 RESEARCH_HILOG.md；验收分层见 VALIDATION.md。

## 真实设备容量验证（2026-10-17）

从当前手机直接采得 13545 行实时 HiLog；另读取设备现存 4 份原厂日志与匹配字典，官方工具输出共 147576 行独立日志，未循环补齐样本。4 份解码均有 unknownlog 提示，标记 partial，不宣称完整还原。

实测最近 100000 行保留正确，淘汰 47576 行；500 行批次追加最大 0.329 ms，全部追加 8.19 ms，快照 4.91 ms，TAG 过滤 2.63 ms，关键词扫描 36.07 ms。文本预算约 38.37 MiB。Node 基准同时持有原文与解析数据，RSS 增量约 170.55 MiB，不能当成浏览器/DSH 整体内存或所有电脑上的保证。虚拟列表避免创建 10 万个 DOM，复杂筛选仍需要扫描保留数据。详细验收边界见 [本轮记录](WORKBENCH_VALIDATION_20261017.md)。

RAR 与编码识别修复及真实设备内容验证见 [修复记录](ARCHIVE_ENCODING_FIX_20261017.md)。
