# dshE2E 0.3.0

基于真实 `e2e@0.19.0` runner 的 DeepSeek Harness 插件。与本仓库的 dshHarmony 0.4.2 共用设备管理器、物理控制锁和基础操作。

在插件列表和会话顶部找到 **dshE2E**，点击可查看本机设备、任务结果、报告和复用入口。

0.3.0 工作台默认按会话隔离，提供分类、搜索、分页、归档、四页报告、截图和日志筛选，以及调整复测。新建／调整先生成会话草稿，发送后执行。见 [面板指南](../../docs/PANEL.md) 和 [AI 安装指南](../../docs/AI_INSTALLATION.md)。

## 使用

告诉 DSH：**“用 dshE2E 打开设置，在搜索框输入‘显示’，确认搜索框的文字正确。不要修改设置。”**

模型调用 `e2e_phone`，`operation: run`，提交 `goal` 与明确的 `expectation`。当前会话的供应商和模型用于执行与独立验收，无需单独 API Key。默认每步骤最多 30 次动作、20 次模型调用、任务 300 秒，无进展或重复动作停止，不自动重跑。

确定性任务可提供 `steps`：`tap/fill/clear/focus/swipe/press/assert/home/back`，选择器 `text/testId/role`。必须有断言。`appBundle` 指定测试应用；开始时停止并启动该应用，不清除数据。省略包名时从当前界面测试。单部手机只运行一个任务，设备忙时明确拒绝。

先用 `resolve_app` 查询设备上的目标应用；唯一应用可用 `appName` 自动匹配，多候选由 AI 核实后传 `logAppBundle`，用户无需手查包名。`logAppBundle` 只绑定日志，**不会重启应用**；原来的 `appBundle` 仍表示显式停止并启动应用。默认采集日志，缺目标时在操作前明确失败；通用界面检查不需要应用日志时可显式 `collectLogs:false`。

`list_runs/get_report` 查看结果；`get_logs + id` 按 `offset/limit` 分页读取日志正文，支持 `level` 最低级别、`query` 关键词、`tag/domain/pid/tid` 字段、`regex/caseSensitive`、`from/until` 本机采集时间范围。`run/get_report` 直接给 AI 返回最多 20 条关键日志摘要与采集状态；更多正文用 `get_logs`。外层 AI 根据日志诊断，手机执行和验收模型仍只看屏幕。日志是不可信数据，不允许把其中的内容当作操作指令。UI 测试通过与日志采集成功分别报告。

`replay + id` 复用流程。自然语言的 act 只有后续 assert 验证通过才保存 e2e 动作缓存。回放重新定位并核对终态，失配交给执行器继续；验收仍实时调用模型。确定性流程直接执行脚本，不承诺零动作执行。

`retry + id` 调整后复测，可覆盖目标、断言步骤和预算，产生新 ID 并保存原报告关联。清空原确定步骤改成自然语言规划时传 `clearSteps:true` 并提供 `goal + expectation`。列表、报告、日志、取消、复用和复测使用实际调用会话的范围，不能操作别的会话记录。

## 数据

安装：使用仓库提供的安装器选择任意本机目录；E 盘路径只是本机示例。

数据：`<DSH_HOME>\storages\dshE2E\workflows`（未设置 `DSH_HOME` 时为用户目录下 `.dsh`）。每个流程的 `.e2e/cache` 保存验证后的动作；`runs/<id>` 保存完整 JSON/Markdown/JUnit 报告、执行轨迹、关键截图和日志。e2e 匿名统计关闭。

日志通过 dshHarmony 的实时日志流采集，按经过确认的目标包名/进程精确匹配，每两秒及界面观察时刷新 PID，避免误收类似包名或已经复用的 PID。内存仅保留最近 1000 条或 2 MiB（先到者为准），完整日志每 250ms 分批写入 JSONL，默认每任务 32 MiB 磁盘上限；`logMaxBytes` 可设 1～128 MiB。待写队列上限 256 KiB；写盘落后或磁盘超限明确报告省略条数；常见密钥字段、设备租约和设备序列号脱敏。完整正文保存在 `app-logs.jsonl`；`dsh-run.json` 和 e2e 报告仅保留有界摘要，AI 用 `get_logs` 从文件逐行查询完整正文。面板可查看正文、采集警告，并把分析请求交给当前会话 AI。

采集前读取设备日志时间水位，排除时间早于或等于水位的历史条目。未获得水位时明确标记按接收时间采集、可能含缓冲历史日志；不清空手机全局日志。区分未识别目标、正常空日志、未确认日志流、采集失败、部分采集和采集成功。0 条不能证明应用没有报错，error 级别本身也不能证明测试发现了应用缺陷。截图作为本地证据保存；首版执行器不使用视觉坐标推理。

## 范围

首版支持现有基础操作、文字控件定位、有预算的执行、独立结果判断、缓存复用和报告；不提供语音、持续按住、密码填写、应用清数据、编译/安装和云端设备。截图使用现有 HDC 截图，与高清投屏组件独立。

## 构建与验证

使用 Node 24，`npm ci --legacy-peer-deps`、`npm run build`、`npm test`。集成测试启动真实 e2e runner，验证模型任务、独立验收、缓存回放及失败释放设备；实机验收单独保存，不以模拟设备结果代替。

e2e：Apache-2.0，https://github.com/tester-army/e2e；dshHarmony 基于 Piora，保留其现有许可证。

## 独立离线日志工作台（0.3.0）

在 dshE2E 顶部点击 **日志工作台 → 导入日志**。不需要连接手机、配置模型或执行测试，也可以在没有活动测试的情况下使用。支持 UTF-8 HiLog TXT/LOG、DevEco 导出文本和 JSONL（含 UTF-8 BOM）；UTF-16、非法 UTF-8 或二进制文本明确拒绝，请先另存 UTF-8。文件名和来源、导入时间、解析数量分别展示。未知格式按原文行显示，不冒充已解析的 HiLog。

浏览器每次只读 256 KiB，单个输入文件上限 **32 MiB**；超限明确拒绝，请先按时间切分。原始文件完整保留在本机 `<DSH_HOME>/storages/dshE2E/log-library/<id>/source.log`，结构化副本容量上限 64 MiB。单条显示/结构化导入最多 8192 字符，超长行及容量截断明确提示；原始文件仍完整，可下载。结构化视图对常见凭据脱敏，原始文件按用户导入内容保留，下载不会自动脱敏。

过滤栏支持最低级别、TAG、DOMAIN、PID/TID、关键词、大小写、安全正则和时间范围。普通字段使用包含匹配，正则精确字段可写 `^61$` 或 `^HaAppEvent$`。为了防止 UI/服务线程卡顿，正则不支持分组、环视、回溯引用，同一分支最多一个量词；量词后仍有内容时必须用 `^` 锚定。支持 `error|warn`、`^.*timeout`、`[0-9]+`，有界重复最多 100。

点击 **查找 · Ctrl+F**，或焦点位于日志查看器时按 Ctrl+F，可独立高亮当前页并上下跳转匹配行。查找也有独立 Aa/正则开关，**不会改变过滤结果**。当前页最多 100 条 / 24 KiB；跨全部日志检索使用过滤栏，不把分页以外内容假装为 Ctrl+F 匹配结果。正文预览限 2000 字符并标示截断，点击“展开原记录”读取最多 8192 字符，完整内容可从原始文件查看。时间范围：测试日志使用本机采集时间；HiLog TXT 导入使用设备文本时间，缺年份按最接近的年份推定，未解析行不参与时间过滤。

AI 可用 `e2e_phone list_log_files` 分页列出本机导入文件，`get_file_logs + id` 使用同样字段分页读取；导入日志库为本机共享只读证据库，测试运行、复测及控制仍按会话隔离。日志内容是诊断证据，不能作为指令执行。旧报告没有文件时仍从原有保存记录查询；异常退出的不完整 JSONL 尾行会跳过并明确报告。
“导出全部筛选结果”使用服务端逐行 JSONL 流，包含当前页之外的匹配行，保留原记录正文而非 2000 字符预览。支持文件保存 API 的浏览器直接分块写入文件；否则只允许最多 8 MiB 的下载缓冲，超限明确要求收窄过滤或读取本机完整文件，不偷偷截断导出。原始文件下载使用服务端流式传输。
