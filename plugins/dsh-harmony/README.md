# dshHarmony 0.3.0

DeepSeek Harness 的鸿蒙设备工作台，适配 Windows 和 DSH Desktop 0.2.0-rc.2。基于 Piora MIT 源码移植，使用当前 DSH_HOME，不读取 Piora 的供应商配置。

## 功能

- 原生 H.264 投屏、点击与拖动、截图、独立 MP4 录像。
- AI 控件树观察、稳定引用、点击、输入、清空、返回、应用启动和有边界的手势。
- 设备应用、文件、终端、数据库、HiLog、诊断、取消和释放控制权。
- 与 dshE2E 共用设备管理，普通动作不会取消只读日志流。
- 可选视觉模型辅助读取屏幕；基础操作与投屏不依赖它。

## 原生投屏

本人的私有安装包内置约 262 KiB 的 ARM64 视频组件，位于 resources/native-video。**无需安装或运行 DevEco Testing，不需要 Java 或投屏 HAP**；仍需要独立 HDC/SDK 和 USB 驱动。

设置中选择“插件原生 H.264”。低开销档请求 15 fps、三分之一尺寸；默认均衡档请求 24 fps、半尺寸；流畅档请求 30 fps、半尺寸。实际帧率随画面变化和设备而变。API 24 实机已验证，其他系统和架构仍需验收。

页面隐藏释放自身预览，回到前台自动连接。静止屏幕可能先显示 JPEG，收到真实 H.264 关键帧才显示实时视频。截图预览不能当作视频成功。组件缺失、损坏或不兼容时明确报告并回退截图，不读取外部 DevEco 安装目录，不安装旧 HAP。

原厂二进制保留原有权利，不受源码 MIT 许可覆盖，仅在本人的私有仓库和安装中使用。组件身份、分析证据、参数修复与性能边界见仓库 docs/NATIVE_VIDEO.md。

## 安装

按仓库 docs/INSTALLATION.md 依次构建和安装 Harmony、E2E。插件数据在 DSH_HOME/storages/dshHarmony。桌面和网页是独立 profile，启动必须固定到正确的 DSH_HOME。

同一设备的视频编码器和控制任务有归属保护；另一服务占用时会显示宿主 PID，不强制清理其他软件。同一手机同时录像与已有预览的共享编码未验收，遇到占用应先关闭预览，再独立录像。

## 开发

使用 Node 24：npm ci --legacy-peer-deps、npm run build、npm test。

私有仓库已包含组件。维护者核对原资源时执行 npm run import:video -- --jar '资源包绝对路径'，未知哈希会拒绝导入。

旧 HAP 通道已经废弃，旧初始化操作只返回明确拒绝，不签名、安装或连接。升级不要删除 DSH_HOME，里面有会话、密钥、供应商与配置。
