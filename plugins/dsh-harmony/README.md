# dshHarmony

将 Piora Harmony 的鸿蒙工作台和 `harmony_control` 工具接入 DeepSeek Harness。上游版本与许可见 `UPSTREAM.json`、`LICENSE-Piora`，保留原有设备租约、跨进程独占、取消、语义节点校验与文件边界。

当前适配目标：Windows，DeepSeek Harness 桌面版 0.2.0-rc.2，Piora 0.5.5-beta.16。宿主升级后需要重新核验插件 API 和 `compat/` 中的 Agent 预设。

## 使用

在会话顶部点击 **dshHarmony** 打开鸿蒙工作台；内置插件列表中显示 **dshHarmony**，提供 `harmony_control`。USB 连接并确认设备调试授权后刷新设备。自动查找 DevEco 的 HDC，也可在设备设置中选择 `hdc.exe`。投屏不会自动解锁手机。

投屏画面支持鼠标点击、按住后拖动并松开执行滑动，以及按住不动后松开执行长按。放大时可用 Alt＋拖动或鼠标中键拖动平移画面。手工点击会按现有规则接管 AI 控制；设备切换、旋转、窗口失焦或取消的手势不发送。AI 控制租约有效期为 20 分钟，后续 AI 设备工具调用继续按该时长续期，任务结束仍释放控制权。

AI 先调用 `operation=prepare_device`：自动选择唯一可控制的手机、取得控制租约、唤醒屏幕并上滑关闭无密码锁屏，返回新的界面摘要。此操作在已亮屏时不会再次按电源键；需要身份验证时明确返回锁屏错误。界面中也有“唤醒设备”按钮。输入只定位可编辑控件，搜索框自动下钻至实际输入字段并校验读回；点击文字引用时，在同一控件祖先链内寻找可点击区域，再执行原有的新鲜度和身份核验。确定的连续步骤优先使用 `run_scenario`，失败会作为 dsh 工具错误返回。

工作台保留上游投屏、截屏录像、设备 Shell、文件传输、应用、日志、数据库、语义场景测试、设备诊断和校准等功能。本机终端使用 dsh 原生终端。视觉模型使用 dsh 的供应商和凭据配置；选中的模型必须支持图片。

设备 Shell 启动期间会缓存有限长度的输入，收到设备提示符后再发送，避免 Windows 启动时吞掉命令。设备命令与设备终端可在工作台搜索；本机终端通过按钮打开 dsh 原生标签，使用其自身搜索。原 Piora 本机终端分屏和统一搜索尚未移植，已去掉失效入口。高清视频组件需要华为开发者登录和设备签名配置；缺失时工作台自动使用免安装截图预览，AI 语义控制不依赖高清视频组件。

网页版和桌面版是独立 profile。安装到一个 profile 不会自动安装到另一个 profile；两者还必须使用正确的 `DSH_HOME`。设备控制具有跨实例独占，同一时间只能由一个实例控制手机。

## 本机安装

构建后，在目标数据环境中执行：

```powershell
$env:DSH_HOME = 'E:\DeepSeekHarness\Data'
dsh plugin --profile desktop add 'E:\DeepSeekHarness\Plugins\dshHarmony'
```

插件数据位于 `$DSH_HOME/storages/dshHarmony`，不会读取或覆盖 Piora 的模型配置。桌面启动入口为 `E:\DeepSeekHarness\Launch-DSH-Desktop.vbs`，桌面和开始菜单快捷方式调用它，显式设置 E 盘数据根目录。

## 开发与验证

源码位于 `src/`，`vendor/` 保留上游实现；`scripts/build.mjs` 生成宿主接口、独立 worker 和浏览器模块。执行 `npm run build`、`npm test`。`scripts/smoke-web.mjs` 检验已启动宿主的身份验证、设备、树和截图；`scripts/control-web.mjs` 在已解锁的真实手机设置页面验证点击、输入读回和返回，结束后释放测试租约。启动 URL 通过临时 `DSH_TEST_URL` 环境变量提供，不写入项目。

手机操作改动保存在 `patches/phone-automation.json`，重新获取上游源码时 `scripts/vendor.mjs` 会按原文件哈希校验并重新应用，避免修复被覆盖。`scripts/wake-smoke.mjs` 验证真实熄屏后的唤醒与重复准备；临时 dsh 会话探针验证工具注册、截图附件、连续语义输入/清空、失败场景、取消和释放。探针只通过独立网页测试服务的临时覆盖配置加载，不安装到桌面启动配置。

插件给 AI 的操作说明包含常用参数和语义批量步骤，避免反复查询完整工具目录；成功动作直接返回更新后的屏幕摘要。`scripts/model-smoke.mjs` 可在独立测试服务中发起真实模型自主操作；`scripts/summarize-model-session.mjs` 从该测试会话的压缩日志核对每次成功操作及搜索、清空、返回和释放，只保存检查结果。模型响应速度会影响整轮任务耗时。

已验收项目和未验收项目以 `artifacts/` 中的报告及任务说明为准。并非所有应用、系统版本和需要签名/校准的高级功能均已完成实机验收。

## 实时视频资源与兼容性

源码仓库中的旧 `OHScrcpyServer.hap` 缺少新版私有签名所需的发行校验记录，不能作为可用的新组件。`resources/harmony-mirror` 使用上游 `v0.5.5-beta.15` 构建 run `37584784712` 的四个公开文件；导入时核对 GitHub ZIP digest，构建时继续核对来源、当前投屏源码指纹、HAP 元数据和哈希及原始验签/验收收据。beta.15 与本次移植的 beta.16 的投屏源码相同；组件来源明确记录为 beta.15，不宣称 beta.16 发布验收通过。重新获取上游源码不会覆盖这份已验证资源。

组件版本 `1.1.27` 最低要求 API 26。当前 nova 14 Ultra 为 API 24，初始化会提前报告版本不兼容，不会生成签名或发送安装命令。开发者登录不能解决这个版本差异，需要兼容 API 24 的组件才能在这台手机启用实时视频。免安装截图预览与 AI 语义操作仍可使用。API 兼容后还需 DevEco 开发者登录和手机签名配置；本机登录入口为 `E:\DeepSeekHarness\Login-Harmony-Developer.cmd`。

### 本机 DevEco 视频桥接（0.2.3）

Windows 优先尝试本机已安装 DevEco Testing 的原生 H.264 视频扩展，再回退到原有视频/截图通道。默认读取 `E:\devecotest\Prograndata\common\resources\screenCastingResource\screenCastingResource.jar`；可用 `DSH_DEVECO_TESTING_HOME` 指定安装根目录。当前适配资源为 `libscrcpy_server_unix_6.6-20260418.z.so`，插件不附带该原生二进制。打开投屏需要手机已解锁，同时请停止 DevEco 自身投屏。成功收到配置和关键帧后才返回视频流；无首帧则回退。关闭时只清理自己的唯一扩展、PID 和精确转发。传输统计保存在插件数据目录 `native-video-cache/native-video-status.json`，是编码画面数量，不能等同浏览器实际显示帧率。

2026-10-11：构建、27 项检查通过；手机自动锁屏后真机视频首帧与显示帧率待验证。

### 投屏恢复（0.2.6）

原生投屏在所有 profile 之间共享设备归属记录。新服务只回收已确认退出的宿主留下的插件专属扩展进程和转发，不清理其他投屏软件。先准备可复用的 UI 驱动，再启动编码器；投屏期间禁止驱动重新初始化，点击和滑动沿用 HDC，精确文字操作复用已连接的驱动。静止屏幕不因无新帧而重连，通过传输错误和设备进程健康检查识别断开。截图回退期间会定期重新尝试实时视频。

0.2.7 补齐官方流程的 `power-shell wakeup`，并在连接视频通道前准备显示和读取画面。不发送电源键、点击或滑动，也不代替身份解锁。视频通过本机直连，不受代理设置影响。界面的启动等待与解码等待分开；可选 UI 驱动准备失败后会退役该 worker，仍允许投屏。占用错误显示具体宿主进程号，失败日志保留通道阶段和插件进程归属，便于区分占用、连接超时与无首帧。

组件在已亮屏且画面静止时仍可能不主动产生 H.264 首帧。此时同一连接先传送有明确标志的当前 JPEG 预览，并显示“画面变化后切入实时视频”；收到实际 IDR 后切换 H.264 并停止预览采集。预览帧数量与编码帧数量分别记录，不能把截图预览当成 H.264 出帧成功。

静止视频的坐标有效性以连接存活、设备代际和当前显示尺寸为依据；不会仅因五秒无新帧而禁用鼠标。视频连接失效或显示旋转时立即拒绝旧坐标。AI 的 UI 树引用和独立截图仍执行原有的新鲜度核验。

### 测试期间持续采集日志（0.2.8）

读取控件树和执行动作只取消相互冲突的被动截图，不再取消只读 HiLog 流。设备停止、断开或宿主关闭仍会清理日志连接。该改动用于 dshE2E 测试期间持续收集目标应用日志；日志过滤、时间水位、截断状态及 AI 正文读取由 dshE2E 0.1.1 管理。
