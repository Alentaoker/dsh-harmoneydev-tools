# 新旧版本差异与改进

当前发布形态为 **v2.3-sdk**。这里的“旧版”指原来的 MCP 取参、只输出属性对照表、HM Symbol 使用 dHash 识别的流程。更早的浏览器 DOM 取参方式继续停用。

| 方面 | 旧版 | 当前版本及改进 |
|---|---|---|
| 任务定位 | 只输出设计属性与鸿蒙资源对照表 | 接入需求、plan 和开发；根据原任务继续规划或实现，避免出表后中断开发 |
| 触发 | 常需要用户提醒查设计 | description 覆盖 UI 改动，并提供 grill/plan 接入约定；呈现不变的纯逻辑不触发 |
| 页面与组件定位 | 容易将同名节点或当前选区直接视作目标 | 核对文件、页面、业务状态和设备形态；有歧义展示候选或问位置，减少取错稿后返工 |
| 属性读取 | 容易混淆外层 spacing、组件定义和实例表现 | 读取实际布局关系、文字区间、变量模式及实例覆盖，记录生效值依据 |
| 资源对照 | 直接值、grep 推断、视觉确认混在一列 | 分开记录设计证据、SDK/工程资源存在与最终实现结论，避免把候选当已确认 |
| HM Symbol | 导出 PNG、缩放、dHash 排序、距离阈值自动绑定 | 从实际单字符读取 Unicode 码点，精确查询目标 SDK 正式成员；去掉图片 hash 与阈值 |
| 资源库 | 依赖旧图库、图形识别或来源混合 | 只由同一目标 SDK 的正式成员与字体 cmap 构建；不纳入社区、字体独有或推断镜像项 |
| 字号与字重 | 容易干扰图片匹配 | 图标身份按字码、样式单独读取；正常唯一命中不逐个要求人工批准 |
| 矢量/图片图标 | 非 HM Symbol 通常直接提示手动导出 | 不做自动匹配；展示目标，由用户选择导出或提供/确认具体 symbol |
| 导出 | 容易作为匹配过程的临时动作 | 明确先展示确切图标、格式和接入方案，确认后才导出，禁止临时匹配绕过 |
| 缺项处理 | 要么盲目继续，要么整个任务停下 | 未决项只阻断依赖它的部分；独立工作继续，不能隐藏未解决项 |
| 遗漏与重试 | 规则多但缺少交接状态 | plan 保留目标/属性/图标/工程状态，按范围检查完成度；复用已读子树，无新线索不重复失败调用 |
| 安装与维护 | 文档、脚本及资源分散，易残留旧逻辑 | 统一目录，提供完整替换与恢复流程；SDK 索引独立保留来源，可按工程重建 |

## 仍然保持的原则

- 设计数据走 Pixso Desktop MCP，截图只作视觉证据，不从截图估数值。
- 不使用 Pixso 的代码生成功能；当前 AI 结合需求与工程实现。
- 只读设计模型，新增素材导出按用户确认范围执行。
- 不随意扩展需求，不为相近颜色或图形强行绑定系统资源。

## 升级时要调整什么

1. 备份旧版后完整替换 skill；旧 dHash 脚本、图片库和社区合并索引不继续加载。
2. 确认目标工程 SDK；旧项目专用索引需核对新 schema，必要时用同 SDK 的资源定义和字体重建。
3. 修改已有 plan 中“取参完成即任务完成”的假设，保留需要继续实现的工程入口。
4. 如需自动触发，把接入约定加到实际 grill/plan 规则；单独安装 skill 不会自动改写上游流程。
5. 用户选择检查 symbol 后，仍需确认具体资源；用户选择导出后，需确认确切节点和接入方案。
