# hdesign-to-arkts

## 目标与边界

让当前 AI 根据用户需求和现有工程实现 UI；设计属性表是开发依据，不是整个任务的终点。用户仅要求查属性时，到取参结果为止；用户要求编写 plan 时，补充 plan 而不提前实现；用户已要求按 plan 开发时，取参完成后继续原开发任务。

- 设计数据只从 Pixso Desktop MCP 读取。不得调用 `design_to_code` 或其他 Pixso 生成代码能力，也不以网页 DOM 替代设计模型。
- 定位、读取与截图不修改设计稿。新增资源导出必须先展示目标图标及处理方案，收到用户针对该方案的确认后才调用导出工具；不得用“临时匹配”绕过确认。
- 系统 symbol 以目标工程 SDK 的 `sysResource.symbol` 正式成员为唯一资源名准入依据；名称存在即确认该 SDK 有此资源，不要求官网或社区二次收录。本包不分发、不查询社区库。字码查询由同一 SDK 字体 cmap 与正式成员连接生成；仅有字体 glyph 而无正式成员的项排除。
- HM Symbol 文字优先按实际字码查询，不使用 dHash。设计图标是矢量、SVG、PNG 或转曲轮廓时，不自动匹配；展示目标截图，让用户选择导出素材或自行确认是否属于 symbol 库。后者需用户提供/确认具体 symbol 名称或对应文字节点，再核对 SDK。
- 不因设计稿出现某页面或状态而扩展需求。工程修改遵循原任务授权与项目规范。
- 按当前环境实际工具描述调用 MCP；`mcp__pixso__*` 是常见命名，不是固定注册前缀。

## 在需求、plan 与执行中接续

识别本次需求是否改变可见 UI。新增界面、控件、状态，或改变颜色、布局、边距、字体、大小、图标，都需要设计依据。仅修改接口、业务逻辑或性能且保持呈现不变时，不强制取参；逻辑变化若新增了可见状态，则只覆盖受影响状态。

1. **需求澄清**：记录要改的页面/组件、设备形态和相关状态。设计范围未明时问业务位置，不让用户先提供 GUID。用户给了大致位置，就优先搜索该范围。
2. **编写 plan**：为受影响区域写入“设计依据”条目：变化范围、来源或定位线索、取参状态、图标处理、工程入口、未决问题，以及开始该区域实现前必须补齐的内容。可按需先定位/取参；无需为纯规划任务遍历整个文件。
3. **执行 plan**：先检查已有条目。复用仍适用的证据，只补缺项；不得把 plan 中的“使用本 skill”当成已经取参。只有对应区域满足下述条件，才开始依赖这些设计值的实现。
4. **继续实现与验收**：主 AI 结合工程组件、资源封装和用户需求编写 ArkTS；检查实际使用的属性和资源与已确认依据相符，并运行项目支持的验证。没有运行界面时，报告尚未做运行效果验证。

如果上游规划流程不会选中本 skill，仅修改 description 不能保证自动触发。将 [交接模板](references/checklist-template.md) 中的“规划流程接入约定”放进现有规划规则；本 skill 不自行修改其他 skill 或项目 AGENTS.md。

## 开始区域实现前检查什么

| 检查 | 通过条件 | 不通过时 |
|---|---|---|
| 目标 | 文件、页面、区域、设备/业务状态与需求一致，有对应依据 | 只做必要定位读取；歧义时给候选截图或询问大致位置 |
| 属性 | 本次修改所依赖的值与布局关系已取得；变量模式、实例覆盖无未解决冲突 | 不猜受影响属性；补查一次有新线索的来源或询问 |
| 图标 | 本次范围内图标都有处理记录，受影响图标所需资源已确认 | 保留未决条目；暂停依赖该资源的部分 |
| 工程 | 已检查本次映射依赖的组件、资源及目标工程 SDK；仅项目明确要求兼容旧运行系统时补查相关兼容条件，仍适用的证据可复用 | 不把其他 SDK 的名称或未选定的图形候选当作最终实现 |

同名节点、相似截图、当前选中、成功返回 DSL 均不单独构成目标确认。用户已明确指定目标且上下文一致，或唯一候选有充分的文件/页面/业务状态证据时，可以继续；不要求每个页面再次人工批准。

缺项只阻断依赖它的工作，其他已授权且独立的工作可以继续。未决项存在时不得宣称该区域完整完成。MCP 不可用时停止依赖 MCP 的取参，说明缺少连接或设计文件，不回退网页取参。

## 防止遗漏与反复试错

围绕“本次视觉改动清单”工作，不全量扫描设计文件或工程。新增/重做区域需列齐该区域可见图标（含实例内部）；局部修改只检查受影响资源，可靠且未变的资源可标记复用。

先核对查询库所属 SDK 与目标工程一致；随包本机 API 26 快照不自动代表公司工程，跨版本需用目标 SDK 重建。已核验字体/SDK 组合中的正常文字图标，唯一字码命中可直接接续实现，无需逐个跑图片匹配或再次人工批准。缺字、无结果、多候选或明显语义冲突时才单独处理。字号、字重差异作为样式属性处理，不当作图标身份不一致。没有实际文本/字体字段的节点不得仅凭 `icon_font` 分类进入字码查询。

读取已返回且足够的子树无需逐个节点重取。组件引用和变量别名使用已访问集合，重复引用不重查，循环、缺失、远程不可达均保留为未决问题。相同失败不原样反复调用；没有新证据时问用户。

完成前核对：本次区域是否都有目标依据；需要的属性是否齐全；图标记录是否覆盖本次范围；是否有未经确认的资源绑定或导出；原开发/规划任务是否已经接续。能并行的工程检索和证据检查可以并行，MCP 读取遵循当前服务的会话限制，不为每个小任务固定创建子 agent。
