# hdesign-to-arkts 使用说明

## 什么时候用

| 场景 | 处理 |
|---|---|
| 新增页面、卡片、弹窗、控件或可见状态 | 规划时定目标和图标处理，实现前取参 |
| 调整颜色、布局、边距、字号、字体、尺寸、圆角或图标 | 只查本次受影响的区域 |
| 按 Pixso 链接实现，或修复与设计稿不一致的走查问题 | 确认页面、设备形态和状态后取参；走查只改不一致的地方 |
| 平板、横屏等适配 | 查对应的设计状态，不默认沿用手机稿 |
| 执行已有 UI plan | 复用 plan 里已取到的值，只补缺的 |
| 用户已给出具体数值，或明确不按设计稿 | 不取参，照用户说的做 |
| 没连 Pixso，用户也没提设计稿 | 说明未对照设计稿，按工程现有规范实现 |
| 接口、缓存、日志、性能等纯逻辑改动，界面不变 | 不用 |

## 怎么调用

一般不用点名，描述 UI 需求即可自动触发。想强制使用时，在消息里写 `/hdesign-to-arkts`，前后要有空格或换行；紧跟中文标点（如 `/hdesign-to-arkts，`）不会生效。

**从需求开始：**

> 帮我梳理并规划订单详情页的退款状态。设计稿里页面很多，找不准时给我候选。

**执行 plan：**

> 按 plan 实现退款提示卡片。

**仅查询：**

> /hdesign-to-arkts 读取这个 Pixso 链接里按钮的尺寸、文字和图标资源，只给结果。

**没有精确链接：**

> 当前 Pixso 文件里“订单详情”页面右上角的操作区，先确认是哪个组件。

## 流程

1. **定目标**：从链接、页面名或业务文案定位；有多个候选时，AI 给截图让你选，你也可以直接在 Pixso 里选中目标后告诉它。
2. **取值**：读取本次需要的布局、尺寸、间距、文字、颜色等；数值来自设计模型，截图用于核对。
3. **图标**：HM Symbol 文字按码点查 SDK 索引，唯一命中直接用；矢量、SVG、PNG 图标集中列出，每个附默认方案，你一轮确认（导出素材或给出 symbol 名）。
4. **实现**：AI 按对照表和工程现有组件写 ArkTS，不使用 Pixso 转代码。
5. **收尾**：说明设计取参、编译、运行核对分别做到了哪一步，以及还有哪些待定项。

写 plan 时就完成第 1、3 步里需要你决定的部分，执行时不再打断。Pixso MCP 的默认服务常见于 `localhost:3667`，以实际配置为准。

## 接入现有 grill / plan 流程（可选）

DSH 会要求模型加载所有适用的 skill，通常只靠 description 就能触发。如果在需求澄清或写 plan 时仍然漏掉，把下面这句加进你实际使用的 plan 规则：

> 本工程以 hdesign/Pixso 设计稿为 UI 依据。需求或 plan 涉及界面呈现变化时，使用 hdesign-to-arkts，并在 plan 里写明设计依据的状态（待取参 / 已取参 / 待定项）。

## 常见问题

- **没自动触发**：先按 [安装说明](INSTALLATION.md) 确认 skill 在 DSH 的扫描目录里，再新开会话；仍不触发，就在消息里写 `/hdesign-to-arkts`（前后留空格）。
- **页面找错**：告诉 AI 页面名、业务入口或大致位置，或在 Pixso 里选中目标。
- **图标没处理**：新增或重做的区域应列出全部可见图标；局部调整只看受影响的图标。
- **SDK 版本不同**：用工程 SDK 的 `sysResource.js` 和 `HMSymbolVF.ttf` 重建索引，见 [hmsymbol-index.md](references/hmsymbol-index.md)。
