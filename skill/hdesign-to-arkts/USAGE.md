# hdesign-to-arkts 使用说明

## 什么时候使用

| 场景 | 如何处理 |
|---|---|
| 新增页面、卡片、弹窗、控件或可见状态 | 在需求/plan 中列设计依据，相关区域实现前完成取参 |
| 调整颜色、布局、边距、字号、字体、尺寸、圆角或图标 | 只查询本次受影响区域及其依赖 |
| 按 UX 链接实现、修复与设计稿不一致的问题 | 确认文件、页面、设备形态和状态后取参 |
| 平板、横屏等适配涉及布局变化 | 查对应设计状态，不能默认沿用手机稿数值 |
| 执行已有 UI plan | 复用仍适用的证据，补齐缺项后接续开发 |
| 改文案、重构或改业务逻辑 | 判断是否改变呈现；有变化只覆盖受影响部分 |
| 纯接口、缓存、日志或性能改动，呈现不变 | 不强制使用本 skill |

不要求每次重新读取整份设计。已有目标与属性证据仍适用时可复用，设计、主题或需求变化时更新相关部分。

## 常见对话

**从需求开始：**

> 帮我梳理并规划订单详情页的退款状态，涉及 UI 的部分用 hdesign-to-arkts 获取设计依据。设计稿里有很多页面，找不准时给我候选位置。

**执行 plan：**

> 按 plan 实现退款提示卡片。先检查设计目标、属性和图标处理是否齐全，再结合现有 ArkTS 组件开发。

**仅查询：**

> 使用 hdesign-to-arkts，读取这个 Pixso 链接里的按钮尺寸、文字和图标资源，只给属性对照表。

**没有精确链接：**

> 当前 Pixso 文件里的“订单详情”页面，右上角操作区域。请先确认找的是哪个组件。

宿主支持 `$skill-name` 语法时，也可以显式使用 `$hdesign-to-arkts`。自然语言自动选择取决于宿主是否发现并加载 skill；只把目录放进 GitHub 仓库不会自动启用。

## 接入现有 grill / plan 流程

将下面约定加入你实际使用的需求澄清 skill、plan 模板或项目规则。安装时只有你授权接入这些规则，AI 才修改对应位置；没有授权时提供待加入内容即可。

> 本工程采用 hdesign/Pixso 作为 UI 设计依据。梳理需求和编写 plan 时，识别本次是否新增或改变颜色、布局、边距、字体、大小、图标及可见状态。涉及时使用 hdesign-to-arkts，或把取参列为对应区域开发前置任务。没有链接时根据已打开文件和业务线索定位；歧义时给候选截图或询问位置。plan 保留目标、属性证据、图标处理和未决问题的真实状态。执行 plan 时先补齐依赖的设计依据，再结合工程实现；禁止 Pixso 转代码。呈现不变的纯逻辑修改不强制取参。

这能让“需要设计依据”在规划阶段被记下来；不能把 plan 写着“调用 skill”当作已经完成取参。模板见 [需求与开发交接](references/checklist-template.md)。

## 完整流程

1. **界定范围**：当前是需求澄清、写 plan、仅查属性，还是已经授权开发；列出本次视觉变化。
2. **连接 MCP**：确认 Pixso Desktop、设计文件和实际 MCP 工具可用。默认服务常见于 localhost:3667，以当前配置为准。不可用时暂停依赖取参的部分，不改用网页扒属性。
3. **定位并确认**：从链接 item-id、明确节点或当前选区取得线索，核对页面、组件、设备与业务状态。没有精确节点时按页面和 frame 缩小范围。有歧义才询问，不反复扫描或自认同名节点就是目标。
4. **提取生效属性**：读取本次所需的布局关系、尺寸、间距、文字、颜色等，按需解析变量 mode、组件引用与实例覆盖。截图用于核对目标和外观，数值来自设计模型。
5. **映射工程资源**：检查现有组件、资源和单位约定；记录原始值、源节点、生效值、实现候选及确认状态。
6. **处理图标**：HM Symbol 文字取实际单 Unicode 字码，在目标 SDK 索引中查正式名称。唯一、正常命中且来源依据适用时继续；缺字、无命中或冲突单独处理。矢量/图片展示给用户决定，不自动匹配。
7. **交接或实现**：仅查属性则输出表，写 plan 则更新计划，已授权开发则根据已确认依据继续实现。未决项只阻断依赖它的部分。
8. **收尾**：说明实现完成情况及剩余问题；工程编译和运行检查按原任务执行，不把有属性表当作 UI 已完成。

## 图标怎么决定

| 实际节点 | 处理 |
|---|---|
| HM Symbol 字体且有单字符文本 | 按实际码点查目标 SDK；字号、字重和颜色作为样式另读 |
| 只有 icon_font 分类，没有实际文字/字体字段 | 不能据此当作有字码，按真实节点数据判断 |
| 矢量、SVG、PNG、转曲轮廓 | 展示目标，让用户选择导出素材或自行核查具体 symbol |
| 用户给了明确 symbol 名称 | 查目标 SDK 正式成员；有资源不等于已经确认它适合当前设计 |
| 查无字码、缺字占位、明显方向冲突 | 保留未决项，不拿相似名称或相似图形直接替换 |

你选择“查 symbol”只是选择处理路径，仍需给出/确认具体名称或文字节点。选择导出时，AI 先说明确切节点、SVG/PNG 格式及工程接入位置；获得确认后导出。PNG 不会因改成 SVG 扩展名而变成矢量。

## 常见问题

- **没自动触发**：先确认宿主能发现同名 skill，再检查 grill/plan 的接入规则。可在新会话显式要求使用它；不靠重复安装碰运气。
- **页面找错**：给页面名、业务入口或大致位置；AI 应展示候选并暂停依赖该目标的实现。
- **没走图标核对**：新增/重做区域应有可见图标处理清单；局部调整仅检查受影响项，可靠旧资源可标记复用。
- **SDK 版本不同**：用目标工程的资源定义和同 SDK 字体重建索引，不能混用随包快照。
- **想直接生成页面代码**：让当前 AI 根据需求、属性证据及工程结构编写，不启用 Pixso design_to_code。
