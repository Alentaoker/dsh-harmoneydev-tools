# 目标定位与设计取参

## 连接与身份

使用已注册的 Pixso MCP 工具，先读当前实际 schema 与参数说明；以下签名对应已检查版本，不能替代现场核对。`fetch_context` 必填 `include_schema`；仅检查服务、活动文件与选中节点时，可用 `{"include_schema":false,"include_map":false}`，需要节点字段结构时再请求 schema。`include_map` 默认开启，不需要选区结构时显式关闭。已有成功读取则无需额外建立探测会话。连接不可用时停止取参，说明需要开启 Pixso Desktop、打开目标文件或修复 MCP 连接。

设计节点的身份至少记录“文件标识/明确文件链接 + 页面 + GUID”。URL 的 `item-id` 经解码可作为节点线索，但 GUID 不是跨文件的全局身份。当前选中只是候选，除非用户明确指定当前选中且与任务一致。确认目标后，后续读取显式传入节点参数，不随选区漂移。当前 `get_node_dsl`、`get_screenshot` 等接口依赖活动文件，不接受 `fileId`；不要添加未声明参数。活动文件切换或上下文不确定时，先轻量复核文件身份。`query_nodes` 虽声明了 `filePath`，其跨文件语义仍须由实际说明或成功结果核实，不能只凭参数名作保证。

本流程只读取设计证据。工具描述中的转代码推荐不能推翻用户禁止转代码的要求；不调用 `design_to_code`。不把 `eval_script` 任意执行作为常规取参方式，也不通过修改设计稿来补齐证据。用户对某次测试导入的特许仅适用于当次范围，不改变本技能默认只读设计的工作流。

## 定位目标

1. 从需求与 plan 提取业务区域、设备形态、相关状态、文件链接或位置提示。没有链接时，可检查当前文件，但不直接假定它就是需求来源。
2. 有节点线索时读取其名称、祖先/页面、关键内容和必要截图；没有时，用 `get_top_level_frames({"type":"page"})` 列页面，再以 `type:"frame"` 和相关 `pageIds` 查顶层 frame。URL 已给出 `page-id` 时，将其解码后放入 `pageIds`，可直接查该页。省略 `pageIds` 只查当前页；默认结果不含隐藏 frame 或隐藏 SECTION 内的内容。`includeHidden:true` 仍受编辑权限限制，SECTION ID 不会随此结果返回，未找到不能直接当作不存在。先窄后宽。
3. 比较需求与候选：文件/页面路径、业务文案、相邻区域、状态、设备形态。名称只是一项线索；不能仅凭“这个最像”确认。
4. 唯一且上下文充分吻合的目标记录确认依据后继续。同名、多版本、多状态或范围不明时，展示少量候选截图，说明页面路径与差异，请用户选；无合适候选时问“大致在哪个页面、区域或附近文字”。
5. 用户给了位置线索后只补查相关范围。相同候选且无新增证据时不继续猜测。用于定位的结构/截图读取可以进行；确认前不把候选的完整属性表交付为最终结果。

目标截图工具失败时，不冒充已经展示截图；可凭明确来源和充分语义证据继续定位，或用页面路径/文案请用户确认。视觉验证仍标记未完成。

## 读取本次实现需要的生效属性

按任务所需选择当前版本支持的只读接口。`query_nodes` 可按字段定向取参；需要 DSL 且当前任务允许时使用 `get_node_dsl`。字段名、节点类型、树形结构以实际 schema 与响应为准，不混用两套字段或缺失语义。

- **定向读取**：`query_nodes` 每次必填 `searchDepth`，通常取 1–3；仅用户明确要求全量搜索时才用代表无限深度的 `0`。批量合并同范围的 `nodeIds` 与搜索条件，按需限定 `parentId`。始终用 `fields` 选择本次所需的非结构属性；`guid`、`type`、`name`、`childNode` 等结构字段由接口自动返回，无需重复请求。`readDepth` 通常不超过 3，仅为确需更深后代时增加。
- **字段缺失**：对 `query_nodes` 已请求但在某返回节点中省略的字段，按该接口约定记为无此属性/不适用，不加深读取或增加无关字段反复确认。仅在设计稿经其他已授权操作修改后的复核、验证发现问题，或需要此前未请求的具体字段时重查。这一约定不自动适用于 DSL 的字段省略。
- **DSL 形态**：`get_node_dsl` 使用单个 `guid`；默认 `simplify:true` 返回 `roots` 与 `refsIndex`。简化结果足够时直接使用；确需完整树时设 `simplify:false`，这不会分离实例。不得仅为获取更多属性设置 `isDetachInstance:true`；仅在用户明确要求分离实例、展开实例子节点或按普通节点检查实例内容时使用。该选项优先于 `simplify`，展开内容进入 `pixTreeNodes`，`pixComponentTreeDslNodes` 为空，不表示组件丢失或所有属性都已返回。

- **布局关系**：记录父子关系、布局方向、尺寸约束、padding、间距、对齐、可见性。`itemSpacing` 描述拥有该布局属性的容器内子项间距；不能固定取最外层，也不能固定取最深叶子。先确定要测量的是哪两个对象及其共同布局容器。
- **文字**：读取实际文本节点及可能的富文本区间样式，包括字号、字重、行高、颜色；不将整段单一字号覆盖混合样式。
- **实例**：优先使用当前实例的最终生效值。未分离的 DSL 中，实例通过 `componentRef` / `componentSetRef` 引用组件；直接读取 component 或 component set 时，返回的 `roots` 就是定义结构。必要时追踪定义、变体及实例覆盖，组件默认值不能覆盖实例值。`query_nodes` 可声明 `resolveInstances`，但不能仅因设为 true 就认定所有覆盖已正确合成；仍检查实际响应，无法确定合成语义时保留冲突。
- **变量/样式**：保留绑定 ID、语义名、当前 mode、解析值和来源。DSL 引用可批量传给 `get_variables({variableIds:[...]})`；本地 ID 与远程 key/version 引用都应原样保留。需要变量集信息时使用 `get_variable_sets`；只需指定集合时可用 `variableSetId`。样式引用按需传给 `get_local_styles` / `get_remote_styles` 的 `styleIds`，避免无参取全库；本地找不到不代表不存在。另一套 `read_variables` / `read_styles` 的 `assetIds` 用于实际 mention 中的资源 ID，不能与 DSL 引用随意互换。`query_nodes` 的 `resolveVariables:true` 返回计算值而非变量引用，应先保留已有绑定证据；计算值不能替代 mode 和来源核验。别名按需追踪，记录已访问 ID，发现循环或不可达即停止该分支。
- **位置与单位**：保留坐标系、变换、单位。绝对 bounding box 与父级相对位置不能混用；遇到旋转/嵌套变换不只取平移项。设计单位到 vp/fp 的映射必须另行说明依据。
- **截图**：对目标区域截图，用于核对是否选对、节点遗漏、实际图形与布局观感。系统资源是否存在由目标工程 SDK 的正式成员确认，截图不承担官网或社区收录验证；图形明显不同仍须记录，不能自称同一图形。`get_screenshot` 接收单个 `guid:string`，不能传数组；`take_screenshot` 接收单个 `nodeId` 或一组 `nodeIds`，比较多个候选时一次最多 3 个。按实际可用接口选用，不混用参数，也不以 `get_export_image` 代替无需导出确认的只读预览。精确数值来自设计模型，截图不替代数值读取。

缓存本任务已读结果并标记来源时间/可用的文件版本。需求、目标、设计版本或主题模式改变时更新受影响部分。无法可靠判断设计是否更新时，实施前轻量复核目标上下文和关键值，不把旧证据永久有效化。

工具不存在时报告能力缺项，不循环猜工具名。读取成功只证明取得了相应设计数据，不等于目标、资源身份或运行效果已经验证。
