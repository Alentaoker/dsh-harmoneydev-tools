# 图标识别与 SDK 资源库

## 唯一的系统资源名准入依据

`v2.3-sdk` 只使用目标工程 SDK 的正式 symbol 成员。`sysResource.js` 中 `sysResource.symbol` 有准确名称，即确认该 SDK 存在此系统资源；无需官网或社区再次收录。本包不分发、不查询社区库，也不使用官网镜像字码补充候选。

资源存在与设计图形是否选对分开记录：SDK 正式名称决定资源是否存在，设计节点、用途和截图决定本次是否应使用它。设计字体来源未知不增加资源存在的审批门槛，但明确的图形差异必须如实保留。

## 本包的数据与构建方式

默认查询库为 `resources/symbol-catalog.json`，来源记录为 `resources/symbol-source.json`，由同一目标 SDK 的以下文件构建：

| 输入 | 用途 |
|---|---|
| `sysResource.js` 的 `sysResource.symbol` 正式成员 | 确定可以按系统资源名使用的名称集合 |
| SDK 自带 `HMSymbolVF.ttf` 的 cmap | 提供 Unicode 码点到 glyph name 的关系，与正式成员按准确名称连接 |
| 可选 SDK 元数据 | 记录 SDK 版本等来源信息，不增加官网或社区准入门槛 |

连接规则：字体 glyph name 必须同时是 SDK 正式成员，才进入字码候选；仅字体中存在的名称直接排除。正式成员没有 cmap 字码时仍保留在库中，支持按名查询，不将其误报为资源不存在。保留确实存在的多候选，不靠字符串相似、去后缀或镜像推测生成系统资源名。

可随包提供本机 API 26 索引快照，具体来源以 `symbol-source.json` 为准。使用前核对目标工程 SDK；本机版本不等于公司工程版本。跨 SDK 版本时，必须使用目标 SDK 的资源定义与字体重建，不能混用某一版本的名称名单和另一版本的 cmap。

示例路径相对于 skill 根目录；构建命令中的路径需换成目标工程实际使用的 SDK 文件：

```text
python scripts/build-symbol-catalog.py --sdk-resource "<目标SDK>/sysResource.js" --font "<目标SDK>/HMSymbolVF.ttf"
python scripts/lookup-symbol.py --codepoint U+F01D5
python scripts/lookup-symbol.py --name bell
```

已取得对应 SDK 元数据时，可为构建命令追加 `--sdk-metadata "<目标SDK元数据文件>"`。构建生成 catalog 与 source；具体输出位置及查询参数先查看当前脚本帮助，不沿用旧版社区合并参数。

离线查询只需 Python 标准库；从 SDK 字体重建时需要 `fontTools`，优先使用已有该依赖的 Python 环境。构建脚本按已验证的 `module.exports.sys = { ... }` 数值对象格式解析 SDK 清单，不执行 JavaScript；遇到其他格式应报告不支持并检查输入，不能执行未知脚本或退回外部图库。

查询也可用 `--text` 传入设计节点的实际单字符。补充私用区字符是一个 Unicode 码点，却可能占两个 UTF-16 码元；不要用 JavaScript `text.length === 1` 判定。码点本身不证明资源身份，查询必须使用已核对的目标 SDK 索引。

## 每个图标的处理顺序

### 1. 保留设计身份与工程上下文

记录文件/节点、用途、状态、组件引用、实例覆盖、实际文本与字体字段，以及可见形态。已有可信资源绑定或同一业务组件的可靠实现时，先查该映射和实际资源；图层名只能作为检索线索。

`fontFamily = HM Symbol` 且有实际文本内容时，优先按字码查询。`query_nodes` 的 `type:icon_font` 不证明它有字码，实际接口可能将导入 SVG 归入此类。没有实际文字、已经转曲或属于矢量/SVG/PNG 的图标，直接进入下述用户选择分支，不自动判断它对应哪个 symbol。

### 2. 在目标 SDK 索引中查询

1. 先确认索引对应目标工程 SDK；同版本且来源仍适用的记录直接复用。
2. 文字型图标从 MCP 读取当前实例的实际文本和字体信息，按 Unicode scalar 解析并查码点，不用截图 OCR。已有准确系统资源名称时可直接按名查。
3. 命中目标 SDK 正式名称即记录“SDK 资源存在”。不要求官网、社区或额外字体库提供第二次收录证明，也不因未做设备运行验证而把名称存在写成未知。
4. 码点查不到时，记录“目标 SDK 索引无此字码候选”。这不等于 SDK 没有同用途资源；可按设计用途查正式名称或相关工程资源，但不得将字体独有 glyph、官网镜像关系或相似名称补进字码结果。
5. 只有项目明确要求兼容较旧运行系统时，才对本次所用资源追加对应兼容检查；没有该要求时，不泛化为所有图标的运行系统确认门槛。

特别是 U+F0A02：若目标 SDK 字体 cmap 指向 `airplane_fill_mirroring`，但 `sysResource.symbol` 没有该同名成员，则按字码返回无候选。不能借旧官网的镜像表自动改成 `airplane_fill`。如果后者确实是 SDK 正式成员，可作为另行按名找到的方案，但必须核对实际方向；需要改变方向或采用仅同形替代方案时让用户确认。

### 3. 正常字码直接使用，异常单独处理

已核验字体来源与 SDK 组合后，可复用该组合的字码对应证据。正常显示的 HM Symbol 文字、单一字码、目标 SDK 唯一命中且无已知例外时，直接接续已授权实现，不为每个图标另跑图片检索、dHash 或人工确认。字号、字重、颜色仍按设计属性实现，不把这些差异判作图标身份错误。区域截图用于定位与整体检查，不作为每个正常图标的独立匹配任务。

遇到缺字占位、无码点命中、多候选或明确的图标含义/方向冲突，再单独核查节点与当前字体 cmap；无法确定时展示目标和问题，请用户判断。字体家族名相同不等于版本相同，字体或 SDK 改变后不套用旧校验结论。没有拿到字体文件时，不能把未查明的问题断言为版本冲突。

### 4. 矢量、SVG、PNG：由用户决定

对矢量、SVG、PNG、转曲图标，展示目标截图、节点路径和用途，然后请用户选择：

1. **导出资源**：提出确切节点、格式和接入位置，确认后导出。矢量优先考虑 SVG；PNG 是位图，不承诺转成 SVG 就能恢复矢量路径。
2. **用户核查是否属于 symbol 库**：等待用户提供/确认具体 symbol 名称或对应文字节点，再验证目标 SDK 正式名称。仅选择“查 symbol”不等于已经选定具体资源。

这个分支不做 AI 图片匹配、相似度排序、dHash、按图层名称猜 symbol 或全库遍历。只有用户明确提供/确认的资源映射才接续实现。已有未改动工程资源可保留引用，但不得据此声称识别了新图标。字码主流程同样不使用 dHash。

### 5. 未决项与导出

按 [资源仲裁](resource-arbitration.md) 展示目标截图、查过的目标 SDK/工程资源、差异和建议。用户确认确切目标与方案后才导出并在已授权开发任务中接入。可继续独立的已确认工作，但未决图标必须保留，不能以相似图标冒充最终结果。

## 维护索引

更新索引时使用同一目标 SDK 的资源定义和字体，记录文件来源、SDK 版本、SHA-256、正式成员数、可按字码查询数及有名无字码项；可选元数据不能代替这两份输入。替换前保留原来源记录，检查字码碰撞、成员新增/移除及同名字码变化。SDK 字体中没有正式成员的 glyph 不进入发布索引；不引入社区库，也不从官网关系补映射。
