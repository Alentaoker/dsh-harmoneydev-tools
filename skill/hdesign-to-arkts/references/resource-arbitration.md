# 资源候选、缺项与导出确认

## 何时需要用户介入

只有当选择会改变结果且现有证据不足时才询问：设计页面有歧义、候选图标难区分、系统资源与设计不一致、需要决定降级或导出等。精确且已确认的资源复用不重复求批准。

目标工程 SDK 的正式 symbol 名称存在，即已确认该 SDK 有此资源；不因官网未收录、社区未收录或设计字体版本未知而另设资源准入审批。本流程不查询社区库。截图用于核对是否选错设计图形；出现明确差异时记录差异，不能声称是同一图形。需要改用另一图形或仅同形候选方案时，展示实际效果并确认影响结果的选择与方向。仅项目明确要求兼容旧运行系统时才把相关兼容问题纳入仲裁。

问题要具体：展示目标节点截图、文件/页面/节点路径、图标用途，以及候选名称/预览与差异。只有目标截图却没有候选预览时如实说明。不要只说“未匹配，自己找”。候选过多时先缩小范围，没有新线索时停止重复检索。

对于矢量、SVG、PNG 或已转曲图标，不先生成匹配候选：展示目标截图，让用户选择“按素材导出”或“由用户核查是否属于 symbol 库”。不做 AI 看图匹配、dHash、相似度排序或根据图层名猜资源。用户选择 symbol 路径后，等待其提供/确认具体名称或文字节点，再核对目标 SDK；选择这个路径本身不构成具体资源确认。可将同一批未决图标集中展示，减少反复询问。

## 用户已选择的导出规则

**先展示目标图标和处理方案，用户确认后再导出。**

方案说明：准备导出的确切节点、导出原因（包括用户直接选择素材方式）、SVG/PNG 选择与预期显示效果、拟放入的项目模块/资源名，以及是否会改变已有引用。展示可通过只读节点截图完成；矢量/图片分支不要求先尝试 symbol 匹配。位图不能仅改成 SVG 扩展名就当作可缩放矢量。

收到用户对该目标与方案的确认后，才调用当前环境实际提供的 `get_export_image` 等导出能力。批准一个图标不等于批准其他图标；已明确批准的一组资源按该范围继续，不反复询问。

确认后仍先核对实际工具 schema。已检查版本的 `get_export_image` 使用单个 `guid`，且必填 `exportSettings`，其中包含 `constraint:{type,value}` 和 `imageType`。约束类型 `1/2/3` 分别为倍率/像素宽度/像素高度，图像类型 `1` 为 PNG、`3` 为 SVG。显式传入获准节点，不依赖可能变化的当前选区；这些参数说明不构成导出授权。

确认前不调用导出工具，不为图片匹配偷偷导出临时 PNG，也不写入工程素材。取参/规划阶段获准导出不自动授权开发任务之外的代码修改。既有未改动资源的复用不属于新增导出。

## 导出后验证与接入

- 核对导出结果是否为预期节点与子层，格式、尺寸、透明背景、裁切和可见形态是否正确。不能把 HTTP 成功当成资源正确。
- 返回可能是临时 localhost URL，也可能是 base64 数据，按实际类型下载或解码并保留二进制；记录来源并确认所得文件确为预期图像。失败时不无限重试，不将报错页或未解码的 base64 文本保存成图片后继续。
- 用户已授权开发时，沿用工程模块、资源命名、适配与主题约定接入；避免覆盖同名资产。按需求选择可缩放格式或足够分辨率的位图，记录格式差异。
- 结合工程检查资源引用与运行效果。尚未验证的事项保留到结果里。

## 缺项如何继续

图标未确定、目标有歧义或映射冲突时，只暂停依赖该项的实现，继续其他独立且已授权的工作。保留现有实现或待办，不自行放一个相似图标当最终结果；用户明确接受临时占位时，记录范围与尚未完成的事项。

在图标清单和 plan 中同步同一条未决问题及下一步。不能因为等待用户而删掉问题，也不能将“列出候选”记为“资源已经确认”。
